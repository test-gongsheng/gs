# 宽基ETF资金流信号系统 设计文档（v1.0 定稿）

> 2026-10-19 讨论定稿。本文档是全工程验收基准：采集层规则、信号规则、
> 界面形态、回测节点全部以本文为准，实现不得偏离；确需调整须先改文档。

## 一、背景与目标

观察：宽基ETF持续大额净流入≈阶段性底，持续大额净流出≈阶段性顶（A股逆向指标，
机制=国家队托底+散户恐慌买指+顶部换仓离场）。

目标：在stock-monitor-v2中建设"市场红绿灯"系统——每日收盘后基于全市场ETF
份额变动计算三池资金流，信号引擎判定顶/底/风格切换，界面顶栏直显，
重点突出、有理有据、提醒醒目。信号未经验证不上线（回测六节点全过才出界面）。

铁律：回测不过，界面不动。醒目的前提是可信。

## 二、数据采集层

### 2.1 数据源（2026-10-19 服务器实测结论）

| 源 | 接口 | 状态 | 用途 |
|---|---|---|---|
| 上交所ETF份额 | ak.fund_etf_scale_sse(date='YYYYMMDD') | ✅逐日、可回溯2024、922只 | 主源（历史回填靠它） |
| 深交所ETF份额 | fund.szse.cn/api/report/ShowReport (CATALOGID=1000_lf, xlsx) | ✅1074只，仅最新一天；akshare封装有bytes兼容bug，须BytesIO+去逗号 | T+1起每日增量 |
| ETF收盘价 | 腾讯 qt.gtimg.cn 批量（系统现有utils/stock_quote.py同源） | ✅ | 金额计算 |
| 东财push2 | - | ❌服务器IP被禁(403) | 禁用 |

净流入口径：净流入 = (当日份额-前日份额) × 当日收盘价。与新浪/证券之星
榜单同口径。已验证：510300在2026-10-15份额246.90→254.85亿份(+7.95亿)，
×收盘≈33.5亿，与新浪公布"510300净流入33.55亿"一致。

### 2.2 全量采集+规则分类（不做抽样）

每日采集两市全量ETF份额（沪市约920只+深市约1070只），按规则引擎分类：

- **宽基池**：跟踪 沪深300/上证50/中证500/中证1000/中证2000/创业板/创业板50/
  科创50/科创100/中证A500/MSCI A50/上证指数/深证100/中证800 等
- **主题池**：半导体/芯片/通信/AI/人工智能/机器人/新能源/军工/医药/酒/券商/
  银行/有色/黄金股等行业主题（用户持仓相关方向全覆盖）
- **固收池**：货币/短融/添益/日利（只放货币+短融；政金债/国债/信用债不纳入——
  机构常规配置不构成撤退信号）
- **策略风格池**：红利低波/红利/自由现金流等（第四类，单独跟踪——
  红利撤向宽基=风偏上升信号，混入其他池都不合适）

分类按"基金简称关键词"自动打标，优先级：固收>策略风格>宽基>主题。
新ETF上市自动归类。映射表落 etf_flow_classification.csv（入git，人工可维护）。

## 三、信号引擎（utils/etf_flow_signal.py）

### 3.1 日度指标（每池）

- 金额：池合计净流入（亿元）
- 广度：池内净流入ETF只数占比
- 头部集中度：前3大流入品种占比（识别单产品异动）

### 3.2 三级信号规则

初版阈值（回测后调参，参数存config不改代码）：

**底信号** = A+B+C：
- A 金额：近5日宽基累计≥500亿 或 单日≥300亿
- B 广度：近5日中≥4天净流入，或当日净流入只数占比≥60%
- C 结构：固收池未同步大幅流入（5日固收净流入<100亿）
- 全中=信号级；A+B=观察级

**顶信号** = A+B+C（防误报核心在B）：
- A 金额：近5日宽基累计净流出≥500亿 或 单日≥300亿
- B 共振：主题池同步净流出（主题净流入则降级为风格切换，不得报顶）
- C 确认：固收池同步净流入
- 全中=真撤退；A+B=观望；仅A=无信号

**风格切换** = 宽基流出+主题流入（差额显著）→ structure-switch，
附方向说明；策略风格池流出+宽基流入 → "风偏上升"提示。

### 3.3 位置过滤

沪深300 PE-TTM近十年分位（数据源：指数估值接口，非东财）：
- 底信号 × 分位<40% → 「底部区域」强
- 底信号 × 40-70% → 「回调窗口」中
- 底信号 × >70% → 降级「高位流入·中继提示」弱
- 顶信号 × 分位>70% → 强；<40% → 弱（低位流出可能是调仓）

### 3.4 输出 data/market_regime.json

regime枚举：bottom_signal / top_signal / structure_switch / risk_up（风偏上升）/
neutral / watch（观察）；信号强度0-100；三池1日/5日金额、广度、估值分位、
一句话中文解读、触发依据逐条明细（每条✓/✗）、数据日期。

## 四、回测验收（上线生死关）

回填2024-01-01至今沪市逐日份额（约660交易日，utils/trading_calendar.py
过滤交易日，sleep≥0.4s防频控），历史价算日度净流入，信号引擎跑全历史，
输出 reports/etf_flow_backtest.md：每个信号触发日、方向、强度、之后5/10/20日
沪深300收益。

**六节点必须全部解释得通：**
1. 2024-02初（国家队救市底）→ 必须出底信号
2. 2024-10-08（3674顶）→ 顶信号或极值预警
3. 2026-01（天量流出8440亿+固收吸金）→ 真撤退命中
4. 2026-07（调整中连续10日净流入760亿）→ 底信号
5. 2026-08（宽基流出755亿但主题流入291亿）→ 必须判风格切换，不得报顶
6. 2026-10-15（高位446亿流入+主力大卖）→ 触发但降级为中继提示

有矛盾→调config重跑，直到自洽。

## 六、工程规范

- 字符编码utf-8，注释中文，与现有文件风格一致；禁止乱码字符
- data/etf_flow/*.csv、market_regime.json 不入git；分类映射表与config入git
- data/stocks.json 持仓文件严禁改动
- 服务器东财禁用时不得引入任何东财源
- 每阶段：自测→中文commit message→push origin master
- 每日16:35全链路任务挂接信号计算（与现有跑批节奏一致）
